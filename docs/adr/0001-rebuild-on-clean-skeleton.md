# ADR 0001：新建骨架，把旧工程当零件库

日期：2026-10-23　状态：已采纳

## 背景

起点是 Ironline 1944（`../origin/sheji`，MIT，Godot 4.7.2，GDScript 约 2.3 万行）。它能运行，射击手感和敌人 AI 都已调好，但耦合很重：

- `GameState` 有 451 行，经济、突破模式、计分、难度、阵营都在里面，几乎所有脚本都读它。
- `bot.gd` 有 2757 行，`player.gd` 有 1386 行，`weapon_system.gd` 有 882 行，都依赖多个全局单例。
- 一大半代码是 MVP 用不到的：载具、商店、突破模式、语音播报、小地图等。
- 素材有 801 MB。

## 决定

不在原地重构，也不从零重写。在 `Battlefield_Rouge/` 新建一个仓库，按 `ARCHITECTURE.md` 的依赖规则搭骨架，再从旧工程逐个搬模块：

- 不依赖全局单例的小模块直接拷贝：`hitbox`、`penetrable`、`cover_point`、各种特效、`weapon_view`、`bot_ragdoll` 等。
- `damageable`、`capture_point`、`weapon_definition` 只依赖一个单例，改几行后搬入。
- `player`、`bot`、`weapon_system` 参考原代码重写成精简版，手感参数照搬。
- 载具、商店、突破模式、阵营、语音、小地图、记分板、天气、DSH 插件、Python 服务不迁移。
- 旧工程的素材一律不带走：9 个武器、4 个角色、4 个载具模型都没有作者、来源和许可证记录，语音包是《无畏契约》的特工语音，录音音效同样来源不明。只迁移代码（MIT），包括程序化生成枪声的 `systems/procedural_audio.gd`。素材改用有明确授权的低多边形素材包，记录在 `docs/ASSETS.md`。

## 后果

- 原地拆耦合时，要同时保证我们用不到的系统不坏，这个成本省掉了。
- 骨架需要先花约一天，MVP 循环会晚一点开始。
- 旧工程更新后不会同步过来，需要时手动对照。
- 将来做架构评审时，不要再建议"回到旧工程原地重构"。
